# 양고 찾기 수정 결과

2026-09-23 · v0.4.0 · 원본 프로젝트를 이어서 수정

## Supabase 연결 준비 추가 사항

요청한 NEXT_PUBLIC_SUPABASE_URL / NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY / SUPABASE_SERVICE_ROLE_KEY 이름을 지원합니다. 서버 키는 server-only 모듈에서만 사용하며 브라우저에 전달하지 않습니다. 서버 비밀값 초기화·읽기 전용 연결 점검 명령을 추가했습니다.

001~008을 합친 새 프로젝트용 production-fresh.sql, 명시적 테이블 RLS·Storage 제한 정책, 실제 DB/RLS/Storage/학년도 연결 상태 확인을 추가했습니다. 기존 업무 API의 성공을 흉내 내는 Mock 저장은 없었으며 실제 Supabase 호출을 유지했습니다.

설정·연결 위치는 SUPABASE_SETUP.md, 실제 개통 검증은 ACCEPTANCE_TEST.md에 있습니다. 현재 공개 링크는 정적 화면이므로 Supabase 설정 외에 Next.js 서버 배포도 필요합니다.

## 이번 계정·권한 변경

- 일반 학생과 모든 관리자 모두 같은 가입·로그인 화면을 사용합니다. 별도 관리자 계정을 생성하는 옛 bootstrap 방식은 폐기했습니다.
- DB 비공개 `admin_allowlist`에 학년도별 후보를 저장합니다. 이름·학번 일치만으로 활성화하지 않고, 사진을 제출한 현재 학년도 인증 요청이 승인되는 트랜잭션에서 권한을 추가합니다.
- ‘관리’ 메뉴는 인증된 임원에게만 추가됩니다. 기존 학생 기능과 본인 내역은 유지합니다. 관리 URL도 서버에서 role을 다시 검사합니다.
- 일반 임원은 역할 변경 불가, 복지부는 학생/전달 임원, 회장단은 학생/전달 임원/복지부 범위만 관리합니다. 최고 관리자 변경은 웹에서 차단하고 서버 전용 절차를 사용합니다.
- 역할 해제는 계정 삭제가 아닙니다. 이전 역할 행과 감사 로그를 유지하고 학생으로 이용할 수 있습니다.
- 학생증 열람·승인은 부장 및 회장단만 가능합니다. SUPER_ADMIN이라는 이유만으로 학생증 API 권한을 주지 않습니다.
- 최초 SUPER_ADMIN도 공통 가입 후 학교 담당자가 서버에서 신원을 확인해 활성화합니다. 첫 인증 담당자가 없는 경우만 별도의 서버 절차를 적용합니다. 자세한 절차는 README에 있습니다.
- 사진·발견 시간·공개 특징·보관번호 등을 입력하는 ‘분실물 직접 등록’을 추가했습니다. 실물 확인·사진 검수·공식 등록·이력 기록은 한 DB 트랜잭션입니다.
- 관리 메뉴에 학생 인증, 등록/실물 대기, 보관/장기 미수령, 소유 확인, 본인 일정/가능 시간, 장소 설정, 관리자 관리, 학년도/인수인계, 기록을 권한별로 연결했습니다.
- 학년도가 바뀌면 역할과 후보 명단을 만료합니다. 이전 기록은 삭제하지 않습니다.

**실제 운영 연결은 아직 완료되지 않았습니다.** 현재 Sites에는 DB 환경변수가 없고 공개 화면은 운영 준비 상태입니다. Next.js 서버와 Supabase 프로젝트의 연결·migration 적용·비공개 Storage·정기 작업·최초 운영자 확인이 필요합니다. 로컬 테스트를 실제 운영 DB 검증으로 표시하지 않습니다.

## 실제 요청 처리 코드

- 학생 가입: 학생증을 비공개 저장소에 업로드하고 가입 신청·PIN 해시를 DB에 기록.
- 인증: 부장 또는 회장단만 학생증 이미지 API 사용. 승인/거절과 삭제 대기 기록은 같은 트랜잭션. 삭제 성공 여부 확인 후 완료 표시.
- 등록: 검수 대기 데이터와 공식 물품을 분리. 실물 확인 전 승인 금지. 내부 보관번호는 별도 비공개 테이블.
- 소유 확인: 요청자의 비공개 설명, 추가 답변, 승인/거절, 물품당 활성 승인 1개.
- 예약: 실제 슬롯 행 잠금과 unique index. 복지부 우선 배정. 학생에게 임원별 개인 가능 시간은 반환하지 않음.
- 수령: 본인 배정만 처리. 번호 확인 및 실제 전달 확인. 물품·요청·예약·이력·번호·알림 원자적 변경.
- 미수령: 예약 종료 후 NO_SHOW 처리, 기존 예약 보존, 물품 보관 및 재예약.
- 장기 미수령: 공식 승인 후 14일 경과를 DB 조회 시 계산. 소유 확인이 승인된 물품은 제외. 자동 폐기 없음.
- 알림: 수신자별 DB 기록과 읽음 상태, 실제 읽지 않은 알림 수. 주기 작업을 통한 예약 임박 알림.
- 인계: 과거 조회, 현재/최초 등록 학년도 구분, 역할 만료, 계정 UUID 유지.

## 실제 운영 연결 상태

**아직 실제 Supabase 프로젝트에는 아직 연결하지 않았습니다.** 사용자 프로젝트의 URL·서버 전용 키·환경변수·최초 관리자 계정이 제공되지 않았기 때문입니다. 코드의 DB 호출은 실제 Supabase API를 사용하도록 작성했지만, 대상 프로젝트에 migration과 환경변수를 적용하는 단계가 남아 있습니다.

정기 실행도 외부 스케줄러 연결이 필요합니다. 즉시 삭제는 인증 API에 연결했고 재시도·만료·예약 임박 알림의 실행 코드를 만들었지만, 배포된 5분 스케줄이 존재한다고 주장하지 않습니다.

## 배포 전 남은 확인

1. Supabase 개발 프로젝트에 migration·private 버킷 적용.
2. 서버 환경변수와 학교가 확인한 최초 운영자/부장·회장단 지정.
3. 실제 Storage의 승인·거절 직후 삭제 및 실패 재시도 검증.
4. 서로 다른 기기의 실제 동시 예약 경쟁·요청 격리·이미지 접근 차단 확인.
5. 5분 정리/알림 스케줄, HTTPS, 운영 고지·보존기간·문의 담당자 설정.
6. 기존 Next.js 서버를 Vercel 등 Node.js 지원 호스트에 배포하고 운영 흐름을 확인. 현재 Sites 공개 링크는 동일 UI를 쓰는 운영 연결 대기 화면으로, 실제 가입·등록·예약은 받지 않습니다.

세부 실행·설정·관리자 인수인계 방법은 README를 참고하세요.

## 학생에게 보여줄 공개 화면

최신 컴포넌트와 CSS를 그대로 사용한 공개 버전을 추가했습니다. 별도 UI를 새로 만들거나 시연 물품을 넣지 않았습니다. 서버가 연결되기 전에는 운영 준비 중 안내를 표시하고 개인정보 입력·전송을 막습니다. 이 링크는 화면 확인용이며 실제 운영 시작을 뜻하지 않습니다.
