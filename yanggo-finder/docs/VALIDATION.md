브라우저 통합 검증은 실제 Next.js 서버 및 Supabase JS 클라이언트가 **테스트 전용 로컬 PostgREST/Storage 어댑터**와 PGlite DB를 사용합니다. 가짜 학생과 물품은 격리된 테스트 메모리에만 생성하며 운영 빌드와 공개 화면에 포함하지 않습니다.

## 아직 검증하지 않은 운영 환경

- 실제 Supabase 클라우드의 migration 001~008 적용, 관리형 Storage 버킷·정책·삭제 API 및 네트워크 장애 후 삭제 재시도.
- 실제 PostgreSQL 다중 연결에서 동시에 예약하는 경쟁 조건. 로컬 테스트는 중복 요청 거부를 확인했지만 부하 테스트는 아닙니다.
- 실제 HTTPS 호스트의 쿠키, 프록시 기반 요청 제한, 환경변수, 학교 최초 운영자.
- 외부 스케줄러의 정기 호출·예약 임박 알림.

공개 링크에는 동일 컴포넌트·CSS에서 생성한 **운영 연결 대기 화면**만 배포합니다. 가입·학생증 제출·등록·예약은 비활성 상태이며, 위 로컬 성공 결과를 실제 운영 환경의 성공으로 해석해서는 안 됩니다.

## v0.4 연결 준비 검증

- `tests/connection.mjs`: 새 설치 SQL 전체를 한 번에 적용, 재실행 거부 확인. 25개 앱 테이블의 RLS 및 Storage 정책 검증.
- anon/authenticated에 실수로 넓은 GRANT·허용 정책을 추가한 상황에서도 제한 정책이 학생 정보와 두 private bucket의 SELECT/INSERT/UPDATE/DELETE를 차단하는지 확인. service_role의 서버 접근은 유지.
- `yg_connection_health`: 정상 schema/RLS/Storage/학년도 검사, RLS가 꺼지거나 bucket이 public일 때 실패 판정 확인.
- 새 환경변수 이름, 누락·서버 키를 공개 키 자리에 입력·잘못된 암호화 키·잘못된 origin 설정 차단 확인.
- `setup:env`: 비밀값 생성과 기존 파일 덮어쓰기 거부 확인. 테스트 임시 파일은 삭제.
- 새 환경변수와 연결 health 검사로 브라우저 가입→승인→물품 등록→예약→반환, 역할 부여/회수, 직접 등록을 검사.
- 프론트엔드 디자인 변경 없음. 기존 프로덕션 빌드 및 TypeScript 검증 통과.

`npm run db:check`를 실제 프로젝트에 실행하거나 실제 Supabase에 migration을 적용하지 않았습니다. 프로젝트 URL·키가 아직 제공되지 않았습니다. 실제 운영 테스트는 ACCEPTANCE_TEST.md를 따릅니다.

## 2026-09-26 Secret Key 업데이트

새 SUPABASE_SECRET_KEY 설정, 기존 변수 호환 및 충돌 차단, 공개 키에 서버 키 입력 차단을 격리 테스트했습니다. 공통 Supabase SDK 전송 설정에서 RPC와 Storage 삭제 요청이 새 키를 apikey로 보내고 키 자체를 JWT Bearer로 보내지 않는지 검증했습니다. 이 테스트는 요청을 가로채며 실제 Supabase에 접속하거나 파일을 삭제하지 않습니다. 실제 프로젝트 키로 db:check 및 전체 인수 테스트는 아직 실행하지 않았습니다.
